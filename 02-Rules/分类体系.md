# 分类体系 (Taxonomy)

> 本文件定义知识库中所有知识点的分类规则，是 schema 层的一部分（[[02-Rules/AGENTS.md]] 的配套文件）。
> 所有 LLM 创建/更新 wiki 页面时必须按本体系标注分类。
> 与用户共同演进：新领域出现时登记到 §2 词表，不要自创游离标签。

## 1. 分类原则

1. **两层各用各的维度**：
   - `01-Wiki/`：目录按**页面类型**（type）组织；主题用 frontmatter 字段 + 标签表达，**不建多层目录**。
   - `00-Raw/`：目录按**知识点**组织（见 §9）——原始资料无 frontmatter，只能靠文件夹分类。
2. **每页必有 domain**：主题领域是一级分类，必须且只能选一个，保证任何页面都能聚合浏览。
3. **标签宁少勿滥**：topic 标签 1-3 个为宜，从词表选，禁止同义标签（如 `AI` 与 `人工智能` 并存）。
4. **分类可迁移**：新知识同时可归入多个 topic，但 domain 取主要领域。

## 2. 分类维度

| 维度 | 字段 | 取值 | 必填 |
|------|------|------|------|
| 页面类型 | `type` | `summary` / `entity` / `concept` / `index` | ✅ |
| 主题领域 | `domain` | 见下方词表 | ✅ |
| 细分主题 | `tags` | 1-3 个，从词表选 | ✅ |
| 成熟度 | `status` | `seedling` / `growing` / `mature` | ✅ |

## 3. Domain 词表（一级主题）

| domain | 含义 | 典型内容 |
|--------|------|----------|
| `tech` | 技术/AI/编程 | LLM、算法、框架、工程实践 |
| `product` | 产品/设计 | 产品思维、交互设计、用户研究 |
| `business` | 商业/投资 | 公司、市场、商业模式、投资 |
| `academic` | 学术/研究 | 论文、理论、方法 |
| `life` | 生活/健康 | 健康、心理、习惯 |
| `reading` | 阅读/人文 | 书籍、人物、思想 |
| `other` | 其他 | 暂未归类的内容，lint 时重新归入 |

**扩展规则**：新领域出现 → 在本表登记一行 + 更新 `log.md`，禁止临时自创 domain。

## 4. Topic 标签规范（细分主题）

- 命名：小写英文连字符（`llm`、`transformer`、`frontend`），避免中文与英文混用
- 粒度：一个 tag 覆盖一个主题簇（cluster），不细分到单篇文章
- 登记：常用 tag 在 §6 索引中登记，便于查询与去重

## 5. 各页面类型的标签要求

| 类型 | domain | tags | 说明 |
|------|--------|------|------|
| summary | 源文件主要领域 | 源文件的主题词 | 继承源的领域 |
| entity | 实体所在领域 | 实体相关主题 | 实体多领域时取主领域 |
| concept | 概念所属领域 | 概念相关主题 | 与引用它的 summary 保持 domain 一致 |
| index | — | — | 索引页不参与分类 |

## 7. 按主题聚合浏览（Dataview）

`index.md` 中的动态区由以下查询生成（需安装 Dataview 插件）：

```dataview
TABLE domain AS 领域, type AS 类型, status AS 状态
FROM "01-Wiki"
WHERE type AND domain
SORT domain, type
```

按领域分组的替代写法（放入 index.md 各小节）：

```dataview
LIST FROM "01-Wiki"
WHERE type = "concept"
GROUP BY domain
```

## 9. 00-Raw 知识点目录规范（RAW 层分类）

> `00-Raw/` 的目录按**知识点（knowledge point）**组织，而非页面类型。
> 一个知识点 = 一个主题簇，与 §6 主题索引（tag 词表）对齐，但粒度更粗（多个 tag 可合并为一个夹）。
> 目的：源文件数量增长后仍能按主题快速定位，而不是全平铺在根目录。

### 9.2 归档规则

1. 新源先落 `inbox/`；ingest 时判定知识点
2. 匹配现有夹 → 移入；**不匹配 → 新建文件夹**（英文小写连字符，与 tag 词表同风格），并在 §9.1 表格**登记一行** + `log.md` 记一笔
3. 文件夹操作仅限**移动**，源文件**内容永不改动**
4. 一个夹内 ≥1 篇即可：宁可单文件独立成夹，也不为凑数硬塞错主题
5. 移动后**同步更新**所有 `[[00-Raw/<夹>/<文件名>]]` 链接（`sources:` 等），避免死链

### 9.3 判定知识点的优先级

1. 源标题 + 正文的**核心主题**（第一优先）
2. 与现有夹的**主题重叠度**（重叠高则归入，不新建）
3. 该源对应 wiki 摘要页的 `tags`（一一映射回文件夹）
4. 仍拿不准 → 归入最接近的夹，并在 `log.md` 标注「⚠️ 待复议」

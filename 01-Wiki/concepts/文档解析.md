# 文档解析（Document Parsing）

> RAG 索引阶段把原始文档转为可检索 Node 的过程；其质量直接决定检索上限——"解析不好，后面再强也救不回"。

## 定义
文档解析是将 PDF/Word/HTML/Markdown 等原始格式转为结构化文本 Node 的环节，包含格式识别、结构保留、分块策略三部分。

## 机制/原理
- **核心矛盾**：检索需小粒度保精准，语义需大粒度保完整——"自包含语义单元"是理想但难达，因不同内容自然边界不同（规格表/FAQ/步骤/概念段落各异）。
- **固定切分三害**：语义边界破坏（句子中间截断）、结构信息丢失（章→节层级扁平）、跨 chunk 信息断裂（FAQ 问答拆散）。
- **结构信息价值**：层级信息防"张冠李戴"；可用元数据注入（`[章节|小节]` 前缀）低成本补上下文。
- **格式难度梯度**：PDF 最难（绘图指令非文本流）→ HTML 噪音 60-80% → DOCX 嵌套结构 → Markdown 最友好。
- **量化指标**：边界准确率>90%、上下文完整性>85%、结构保留率>95%、端到端检索质量。

## 例子
```python
def add_structural_context(nodes):
    for node in nodes:
        node.metadata["section_path"] = f"{chapter} > {section_title}"
        node.text = f"[{chapter} | {section_title}]\n{node.text}"
```

## 边界与常见误区
- 不存在"永远最优"的 chunk_size；与文档类型/语言/问答粒度/上下文长度都有关。
- 解析是 RAG 质量的"一半决定因素"，非纯模型问题。
- 元数据注入是低成本高收益手段，但无法替代真正的结构解析。

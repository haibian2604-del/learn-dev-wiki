# 规划模式（Planning）

## 定义

让模型**自主决定**完成复杂任务所需的步骤序列与工具调用顺序，而非由开发者硬编码。属于高度自主的 Agent 形态（→ [[01-Wiki/concepts/Agentic AI 工作流]] 自主性光谱的高端）。

## 机制/原理：四步落地

1. **提供工具集**——把可用工具及说明交给 LLM
2. **LLM 编写计划**——要求它返回逐步执行计划，说明按什么顺序调用哪些工具
3. **逐步执行**——把每步指令与上一步输出/上下文依次喂给 LLM，让它调用相应工具
4. **最终输出**——把所有步骤结果反馈给 LLM 生成最终答案

## 三种计划表达方式（递进）

| 方式 | 做法 | 优缺点 |
|------|------|--------|
| 自然语言计划 | LLM 直接讲出规划 | 直观，但**不够清晰明确，下游代码难以稳定解析** |
| **结构化计划（JSON/XML）** | 指示词："你可以访问以下工具，并需要以 JSON 格式创建一个分步计划"，并详细描述 JSON 结构 | 每步含 `description` / `tool` / `arguments`，解析器编写非常方便 |
| **代码即行动（code-as-action）** | 让 LLM 直接写 Python 代码表达多步骤与工具调用 | 可利用 Pandas 等大库、表达力高；**论文普遍显示评估分数高于写 JSON 再解析** |

> 结构化计划的典型返回：`[{description, tool, arguments}, ...]` → 转 JSON → 提取参数 → 执行对应函数。

## 例子（客服助理 Agent）

目标："你们有没有库存中售价低于 100 美元的圆形太阳眼镜？"工具集：`get_item_descriptions` / `get_item_price` / `check_inventory` / `check_past_transactions` / `process_item_sale` / `process_item_return`。

LLM 自主产出的计划：① 调 `get_item_descriptions` 找 round sunglasses → ② 据 Step 1 输出 → ③ 调 `check_inventory` 查库存 → ④ 对有货结果 → ⑤ 调 `get_item_price` 筛出低于 $100 → ⑥ 输出结果。

## 工具设计是关键难点

同一场景下：

- 有经验的开发者：抽象出 **3 个封装好复杂逻辑的核心工具**即可
- 经验不足者：要么**过度抽象出十几种工具**，要么只给一两个最基础的工具——**极端反例是直接把后台数据库 session 交给模型让它自己写业务代码，这是极其不安全的**

## 边界与常见误区

- **风险**：运行时无法预知 LLM 会生成什么计划 → 结果不稳定 / 出错 / **越权**
- **现状**：规划模式在 **AI Coding 应用中非常成功**，其他领域仍处尝试阶段
- **取舍**：难以控制，但放弃部分控制权能显著扩大能力范围，**多数时候值得**
- 对比 [[01-Wiki/concepts/任务分解]]：任务分解是人静态拆好的结构；规划模式是模型运行时动态决定顺序
- 代码执行路线的安全要求与 [[01-Wiki/concepts/代码执行]] 相同：**必须沙盒**

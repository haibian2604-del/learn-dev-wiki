# 查询路由（Query Routing）

> 在 [[01-Wiki/concepts/GraphRAG]] 中，按查询特征自动选择最合适检索策略的机制：简单查询走传统混合检索，复杂推理走图检索，中等复杂走组合检索。

## 定义

智能查询路由器（IntelligentQueryRouter）分析查询的复杂度/关系密集度/推理需求/实体数，输出推荐策略，再分派给对应检索引擎，并在失败时降级。

## 机制/原理

**四维度查询分析（LLM 驱动，输出 JSON）**
- 查询复杂度 (0-1)：0.0-0.3 简单信息查找；0.4-0.7 中等；0.8-1.0 高复杂推理
- 关系密集度 (0-1)：单一实体 / 实体间关系 / 复杂关系网络
- 推理需求：是否多跳·因果·对比
- 实体识别：明确实体个数
- 推荐策略：`hybrid_traditional` / `graph_rag` / `combined`，附 confidence 与 reasoning

**规则降级**：LLM 分析失败时，基于关键词（"为什么/如何/关系/影响/比较"等）做规则判定，保证可用性。

**三种核心检索策略**
1. **传统混合检索**：三路召回（实体+主题双层检索 + 向量检索 + BM25/jieba）→ RRF（Reciprocal Rank Fusion，`score=Σ1/(k+rank)`，k 默认 60）融合；可选父文档回填（命中 chunk → 整篇父文档，保证步骤类问题上下文完整）
2. **图 RAG 检索**：按查询类型走多跳遍历（MULTI_HOP/PATH_FINDING）/ 子图提取（SUBGRAPH）/ 实体关系（ENTITY_RELATION），再做图结构相关性排序
3. **组合检索**：传统与图结果各取一半，Round-robin 轮询交替合并（参考 LightRAG），自然均衡多样性

**决策规则（阈值）**
- 复杂度 < 0.4 → 传统混合检索
- 复杂度 > 0.7 或 关系密集度 > 0.7 → 图 RAG 检索
- 0.4 ≤ 复杂度 ≤ 0.7 → 组合检索

**多跳推理价值**：传统检索只找直接匹配；多跳能发现隐含关联（如"鸡肉 → 宫保鸡丁 → 胡萝卜 → 蔬菜类别"，推断鸡肉常配胡萝卜）。

## 边界与常见误区

- 路由本身有成本（每次查询多一次 LLM 调用）；低延迟场景需权衡
- 降级设计必备：高级策略失败自动回退传统检索，传统失败才报异常
- RRF 按 `node_id` 去重，三路候选空间需留够（否则融合退化）

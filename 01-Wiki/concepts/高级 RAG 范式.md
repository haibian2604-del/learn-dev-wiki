# 高级 RAG 范式（Advanced RAG Paradigms）

## 定义

- 相对"固定两步（先检索一次、再生成一次）"的基础 RAG，高级范式的共同点是**把检索变成由模型按需控制的多次过程**——决定"要不要检索、检索几次、检索结果够不够好、要不要换查询"。
- 一句话：**基础 RAG 是流水线，高级 RAG 是带控制器的闭环**。

## 机制/原理

### 一、四条演进线

| 范式 | 核心机制 | 解决的问题 |
|------|----------|------------|
| **迭代检索**（Iterative / Multi-hop，如 IRCoT） | 检索 → 推理 → 用中间结论驱动下一轮检索 | 多跳问题（"A 的创始人在哪读书"） |
| **自适应检索**（Self-RAG / Adaptive-RAG） | 模型输出**反思 token** 或由分类器判难度，自己决定要不要检索 | 简单问题不必检索，省成本 |
| **纠偏检索**（CRAG, Corrective RAG） | 评估召回质量：正确→直接用，模糊→补检索，错误→换源（如转 Web） | 召回质量不可靠 |
| **查询侧改写**（HyDE / 多查询扩展 / **子问题分解**） | 改写或拆解问题后再检索 | 问题表述与文档表述不匹配 |

### 二、子问题分解（最常被追问）

**触发**：query 含多实体、多个问号、并列连接词，或首轮检索结果分散/低分。

**流程**：
1. **分解**为 N 个自包含子问题
2. **消解指代**，让每个子问题能独立检索（否则检不到）
3. **并行检索**各子问题
4. **按需递归**（限最大深度，防爆炸）
5. **聚合**：证据齐备则生成，缺失则补检索或明确"无法回答"

**两种实现**：
- **Plan-then-Execute**：先一次性规划（延迟低，计划可能不优）
- **Interleaved（IRCoT 式）**：边推理边发问（更准，轮次多成本高）

**必备约束**：子问题数量上限 + 最大递归深度 + 总预算 + 冲突消解规则。

### 三、结构增强型（另一条路线）

- **GraphRAG**：图谱负责多跳与全局性问题（→ [[01-Wiki/concepts/GraphRAG]]）
- **RAPTOR**：递归聚类建摘要树，层级检索（先命中摘要层再下钻原文）
- **Parent-Child 分块**：小块检索、大块生成（工程上最划算，→ [[01-Wiki/concepts/文本分块]]）

### 四、成本控制（真正的工程难点）

高级范式的收益是准确率，代价是**成倍的延迟与 token 成本**。生产必须配：

1. **难度路由**：先判问题难度——简单直接答 / 中等单次检索 / 复杂多步
2. **最大轮次与预算上限**：没有上限一定会空转
3. **收敛条件**：证据齐备即停、收益递减即停、相同查询去重
4. **降级路径**：多步失败 → 退化为单次检索 + 拒答

## 例子

**问题**："A 公司和 B 公司的 RAG 方案有什么不同？"

- 基础 RAG：直接用原问题检索 → 召回到 A、B 各自的零散片段 → 对比不完整
- 高级 RAG：
  1. 分解为 ①A 的方案 ②B 的方案 ③对比维度
  2. 三路并行检索
  3. 聚合并检查证据齐备
  4. 缺失则补检索，齐备则生成结构化对比
- 成本：检索次数 1 → 3+，延迟上升，需难度路由判断"这是否值得走重链路"

## 边界与常见误区

- ⚠️ **不加限制就上多步**：延迟与成本翻倍，且容易陷入"再搜一次"的空转——**没有预算上限的多步检索是事故**
- ⚠️ **简单问题也走重链路**：绝大多数问题单次检索即可，全量上高级范式是过度设计
- ⚠️ **Self-RAG 式自反思不可靠**：模型自我评估召回质量的能力有限，需外部信号（环境真值/独立评估模型）兜底
- ⚠️ **与"查询路由"混淆**：路由决定"走哪条链路"，高级范式决定"链路内走几步"，二者是配合关系
- **不是越复杂越好**：复杂 ≠ 更好，很多场景**换更好的嵌入模型或加 rerank** 的收益更高、成本更低

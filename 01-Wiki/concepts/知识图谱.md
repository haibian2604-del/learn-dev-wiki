# 知识图谱（Knowledge Graph）

> 用"节点（实体）+ 边（关系）"的网络结构，把离散知识显式组织成交互联的语义网络，是 [[01-Wiki/concepts/GraphRAG]] 的底层结构。

## 定义

知识图谱以图的形式直接编码实体间的显式语义关系（如"公司A - 收购 - 公司B"），而非让 LLM 从文本中隐式推断。节点 = 实体（带属性），边 = 关系（可带属性、来源、时间戳、置信度）。

## 机制/原理

**核心优势（赋能 RAG）**
- **结构化语义表达**：显式编码关系，提供清晰导航路径
- **增强推理**：图天然支持多跳推理，沿路径遍历发现间接关联
- **事实性与可解释性**：答案可追溯到图中的推理路径，抑制幻觉
- **异构数据集成**：无缝融合结构化（DB）与非结构化（文本）数据

**进阶能力**
- 语义模式与本体（Schema/Ontology）约束实体类型、关系、属性域，降低歧义
- 溯源与置信度管理：边/节点携带来源·时间戳·置信度，便于归因与冲突消解
- 时间/版本建模：时间态边与版本化节点支持"历史状态/有效区间"查询（Time-travel Query）

## 例子

图RAG 菜谱图谱（→ [[01-Wiki/summaries/图数据建模与准备]]）：
- 实体类型：Recipe（菜谱）、Ingredient（食材）、CookingStep（步骤）、CookingMethod（技法）、CookingTool（工具）、DifficultyLevel（难度）、RecipeCategory（分类）
- 关系类型：`REQUIRES`（菜谱-食材，含 amount/unit）、`CONTAINS_STEP`（菜谱-步骤，含 step_order）、`HAS_DIFFICULTY_LEVEL`、`BELONGS_TO_CATEGORY`
- 查询示例（Cypher）：`MATCH (r:Recipe)-[:REQUIRES]->(i:Ingredient) WHERE i.name CONTAINS "虾" RETURN r.name, i.amount`

## 边界与常见误区

- 图谱质量决定上限：抽取错误/遗漏会直接污染下游检索
- 构建本身是知识工程，耗时耗力；生产需动态更新机制
- 不是所有查询都需图：简单事实问答用向量检索更便宜

# 实体关系抽取（LLM-based KG Construction）

> 知识图谱构建的第一步：用 LLM 从非/半结构化文本中识别实体、关系与属性，输出图数据文件后再导入图数据库。是 [[01-Wiki/concepts/GraphRAG]] 与 [[01-Wiki/concepts/知识图谱]] 的构建入口。

## 定义

实体关系抽取（Knowledge Extraction）利用 LLM 或 IE 管线，从文本中抽取 (实体, 关系, 属性) 三元组，是图谱构建阶段的核心步骤。

## 机制/原理

**标准流程（→ [[01-Wiki/summaries/图数据建模与准备]]）**
1. 读取源文档（如 Markdown 菜谱）
2. **LLM 解析提取**：识别并抽取实体及关系
3. **结构化输出**：生成 `nodes.csv`（节点）与 `relationships.csv`（关系）
4. **图导入**：通过 Cypher 脚本导入 [[01-Wiki/entities/Neo4j]]

**CSV 结构**
- nodes.csv 列：nodeId, labels, name, preferredTerm, fsn, synonyms, category, difficulty, cuisineType, amount, unit, stepNumber, methods, tools ...（统一编码 `nodeId` 唯一标识，多语言 + 丰富属性 + 层次化）
- relationships.csv 列：startNodeId, endNodeId, relationshipType, relationshipId, amount, unit, step_order

**配套工序（来自 GraphRAG 通用框架）**
- 指代消解、别名归一（Normalization）、术语标准化
- 质量控制：三元组置信度评估、人机协同抽检、冲突消解
- 图谱融合：实体对齐与去重（Entity Resolution），合并跨来源知识并保留来源/时间戳

## 例子

菜谱图谱抽取结果：Recipe-REQUIRES-Ingredient（含用量）、Recipe-CONTAINS_STEP-CookingStep（含顺序）、Recipe-HAS_DIFFICULTY_LEVEL、Recipe-BELONGS_TO_CATEGORY。

## 边界与常见误区

- 抽取质量决定图谱天花板：错误/遗漏直接污染下游检索
- LLM 抽取需抽检与一致性校验（本体/Schema 约束），不可全信
- 实体对齐去重是关键难点，跨来源同名/异名需归一

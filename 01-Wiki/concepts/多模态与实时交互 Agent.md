# 多模态与实时交互 Agent

## 定义

能听、能看、能操作界面的 Agent——语音输入/输出的实时对话系统（Voice Agent）与直接操作图形界面的自主 Agent（Computer Use / GUI Agent）。**多模态不是"给文本 Agent 加个语音/视觉接口"，而是重新设计感知-决策-执行循环**：延迟约束、信息密度、错误恢复方式完全不同。

驱动因素：用户场景要求（客服/车载/家居手眼被占用）、任务复杂度要求（网页/桌面长尾应用无法纯 API 覆盖）、模型能力到位（2025-2026 密集发布，延迟成本降到可用）。

## Voice Agent 三种架构范式

1. **Cascaded 级联**：VAD → ASR → LLM → TTS。每环节独立优化替换、LLM 部分与文本 Agent 完全复用；延迟=各环节之和（约 1.3s+）；语调情感在 ASR 丢失。可控性最高。
2. **Omni 端到端**：单一多模态模型音频进音频出。延迟极低（300-500ms）、保留副语言信息；可控性差（黑盒）、调试困难（无中间文本）、成本高。
3. **Full-duplex 全双工**：可打断、边听边说。最接近自然对话；需处理同时说话冲突、打断检测（独立模块）、流式生成+播放+随时取消。500-800ms。

实践常用**混合方案**：Omni 做快速短回复，Cascaded 做需工具调用的复杂回复。

## Computer Use / GUI Agent

- **动作空间**：有限动作原语（click/type/scroll/key/screenshot/wait/drag）。原则：原子性、可逆性标注（不可逆操作需确认）、等待机制（操作后等渲染再验证）。
- **视觉定位**：Set-of-Mark（SoM 标号选择，LLM 只需选 ID 不需空间推理，遗漏元素无法操作）vs 坐标定位（无需检测但精度依赖模型视觉、分辨率变化失效）。实践：优先 SoM，fallback 坐标。
- **安全边界**：环境隔离（沙箱/虚拟机）、权限收窄（白名单应用）、操作审批（不可逆人工确认）、执行限速（防高频点击循环）、状态验证（操作后截图对比）。
- **代表产品**：Claude Computer Use、Open Interpreter/OS-Copilot、RPA 增强、浏览器自动化（Playwright/Puppeteer+视觉）。共同架构：截图/DOM → 理解 → 规划 → 执行 → 验证 → 循环。

## 快慢解耦：跨模态共性设计原则

核心矛盾：用户期望实时响应（快），深度推理需要时间（慢）。方案：**实时响应通道与深度推理通道分离并行**。

- Voice：快通道给填充词/短确认维持节奏，慢通道做语义理解/工具调用/回复生成
- GUI：快通道按已有计划执行下一动作，慢通道每隔 N 步或异常时全局重规划

本质是"缓存 + 后台刷新"的交互版本。此原则在 Embodied Agent 中体现为**双层架构**（高层规划 VLM/LLM 秒级重估 + 底层控制 VLA/Policy Network 毫秒级执行，控制层不直接使用大模型输出需过安全过滤器）；**Action Chunking**（一次预测 0.5-1s 动作序列 chunk，控制器 50-200Hz 回放）弥补推理频率鸿沟；**Sim2Real**（仿真中获泛化、真实中获精度）。

## 工程挑战

- **延迟预算硬约束**（Voice 总预算 ~800ms）：流式处理（LLM 出首句即开始 TTS）、预计算、分级降级（模板回复/短确认）
- **多模态信息对齐**：统一时间轴（时间戳排序）、显式引用消解（prompt 中解析指代）、状态快照（截图+文本+音频）
- **错误恢复**：检测-确认-恢复三步循环（Voice 主动确认/复述；GUI 每动作截图验证/回退），不盲目重试

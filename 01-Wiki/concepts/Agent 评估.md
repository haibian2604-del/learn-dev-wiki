# Agent 评估（Agent Evaluation）

## 定义

建立 Agent 质量的工程判断标准：**用什么标准、什么方法判断 Agent 的表现**。"能跑"与"好用"之间的差距需要可验证的评估体系弥合。与一次性测试不同，Agent 评估是贯穿系统全生命周期的工程实践。

传统软件测试假设"相同输入产生相同输出"，Agent 打破该假设（输出随机性、工具路径不同、多正确解、中间过程也要评估），不能只套单元测试思路。

## 四个评估维度

1. **任务完成率（Task Success Rate）**：是否真正完成任务。"完成"= 可被外部验证的结果（测试通过/关键事实/格式规范），而非模型自述。关键是定义明确验收条件。
2. **效率（Efficiency）**：迭代次数、token 消耗、工具调用次数（无效/重复）、端到端延迟、费用。完成率相同 3 轮 vs 12 轮质量差距大。
3. **安全与合规（Safety）**：越权工具、信息泄露、不合规内容、信息不足时编造事实。Demo 阶段几乎不测，生产中可能最重要。
4. **鲁棒性（Robustness）**：模糊/恶意输入、工具报错超时、上下文极长极短、中断恢复。不是"永远不出错"而是"出错时行为可预测且可恢复"。

## 四种评测方法

1. **固定测试集 + 自动验证**：有明确预期结果的用例自动比对。可重复可回归；只覆盖有限场景。
2. **LLM-as-Judge**：另一模型打分（准确/完整/相关）。可评估开放式任务；评判模型有偏差需校准。原则：明确评分标准与示例、多次取平均、定期人工校准、**不让自己裁判自己**。
3. **A/B 对比**：同批任务两版本分别处理比较。回答"新 Prompt 好多少 / 换模型是否降质 / 某步骤是否值得成本"。
4. **对抗性测试（Red Teaming）**：专门设计让系统出错的输入（注入/边界/矛盾指令/越权请求）。追求"最差情况下系统会不会失控"。

## 实用建议

- 小测试集起步（20-50 用例 + 自动化脚本）；区分**能力评测**（Mock 工具控制变量验逻辑）与**集成评测**（真实工具端到端验生产）；≥30% 测试覆盖异常边界；同用例至少跑 3-5 次注意统计显著性
- **持续监控 > 一次性评测**：成功率趋势、平均迭代次数、token 异常增长、用户反馈、工具失败率——突变往往意味外部依赖或数据漂移
- 陷阱：只测 happy path / 把"模型说完成了"当真 / 忽略成本维度（10 轮 vs 3 轮成本差 3 倍）/ 过度依赖 Benchmark（任务分布/工具环境/成功标准不同；Benchmark 用于选模型定基线，业务评测验证系统）

## 与 Loop Engineering 的关系

相互支撑：Loop 退出条件需评估触发（Verification Loop 验证器本质是实时评估器）；评估指标驱动 Loop 策略调优；持续监控发现退化触发评测分析根因。

## 补充视角：训练评测（learn-agent-training 05）

> 来自 [[01-Wiki/summaries/Agent 评测：怎么衡量你训练出来的 Agent 到底行不行]]：评测"训练出来的模型"时，RL Reward 曲线在涨不代表真的变强。

- **与运行时评测互补**：运行时评测看"线上 Agent 好不好"（本页上半部分）；训练评测看"模型训练完行不行"（四层指标 + 评测环境 + 防泄露）
- **四层指标**：任务完成（Pass Rate / Partial Score / **Pass@k**——Pass@1=60% Pass@5=85% 说明有能力但稳定性不够，RL 应聚焦稳定性）、效率（步骤数/冗余率/首次成功率/Token）、鲁棒性（错误恢复率/指令扰动稳定性/上下文长度/工具缺失处理）、安全（危险拒绝/Prompt 注入抵抗/权限越界/确认率）
- **评测环境三方案混合**：核心功能 60%（沙箱+自动验证）+ 开放式 25%（LLM-as-Judge）+ 快速回归 15%（静态数据集，适合 CI/CD）；评测集构建注意与训练集**无重叠防泄露**（不同人/方法构建、发布后冻结）
- **五大陷阱**：只看完成率忽视效率（综合效率分 = 完成率 × 基准步骤/实际步骤）、评测集太简单（按难度分层看）、评测环境与生产不一致（**注入真实噪声**：随机 5% 超时/3% 格式异常）、Judge 系统性偏差（长度/格式/自我/位置偏好）、训练与评测分布泄露（全新任务复测）
- **三阶段流程**：训练中快速评测（每 500-1000 步，10 分钟出结果）→ checkpoint 全面评测（300-500 条四层指标）→ 上线前灰度评测（生产流量 A/B）
- **Benchmark**：公开 Benchmark（SWE-bench/WebArena/ToolBench/GAIA/AgentBench/HumanEval）对标业界，自建评测集评估业务，两者缺一不可

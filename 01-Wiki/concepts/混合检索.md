# 混合检索（Hybrid Retrieval）

> 同时执行向量搜索（语义）与关键词搜索（BM25 精确），再用融合算法合并结果，取长补短。

## 定义
把 dense（向量语义）检索与 sparse（BM25 关键词）检索组合起来，对两者的候选结果做分数融合，得到比任一单一方法更稳健的 Top-K。

## 机制/原理
- **为何混合**：纯向量遇专业术语/罕见实体/精确编号易失配；纯关键词遇同义词/语义理解无能为力——互补非替代。
- **分数融合是核心**：余弦相似度[-1,1] 与 BM25[0,30] 量纲不同，不能直接相加。
- **RRF（Reciprocal Rank Fusion）**：`score(d)=Σ 1/(k+rank_i(d))`，k 默认 60。按排名而非原始分数融合，任一方法表现优异者即脱颖而出。
- **LlamaIndex 实现**：`QueryFusionRetriever(retrievers=[vector_retriever, bm25_retriever], mode="reciprocal_rank")`。mode 还支持 `relative_score`（保留原始分数比例）、`simple`（简单平均）。
- **权重调优**（relative_score 模式）：自然语言多→向量 0.7+；精确术语多→关键词 0.5+；不确定用默认 RRF。

## 例子
```python
hybrid_retriever = QueryFusionRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    mode="reciprocal_rank", similarity_top_k=5,
)
query_engine = RetrieverQueryEngine.from_args(hybrid_retriever, response_mode="compact")
```

## 边界与常见误区
- 误区：混合永远更好。否——查询类型一致且数据均匀时可能无提升，反而增复杂度/延迟；先评估再引入。
- 误区：BM25 只能英文。否——LlamaIndex BM25Retriever 用 jieba 支持中文，专业领域可加自定义词典。
- 误区：RRF 的 k 需仔细调。否——k=60 几乎总是好默认，调优精力放 chunk_size/嵌入模型/top_k。
- 开销：BM25 倒排索引额外内存（百万节点数百 MB）；额外延迟 20-50ms。

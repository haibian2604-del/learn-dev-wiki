# Agent 记忆系统（Agent Memory）

## 定义

- Agent 在**上下文窗口之外**持久保存与检索信息的能力层，使 Agent 能跨轮次、跨会话保持一致性，而不受 token 上限约束。
- 与 [[01-Wiki/concepts/上下文工程]] 的分工：上下文工程解决"**这一轮该给模型看什么**"，记忆系统解决"**信息该存在哪、什么时候取回来**"（→ [[01-Wiki/summaries/Context、State 与 Memory]]）。

## 机制/原理

### 一、分层（按时间尺度）

| 层 | 载体 | 生命周期 | 说明 |
|----|------|----------|------|
| 工作记忆 | 上下文窗口 | 单次调用 | **token 预算管理**是核心：给系统提示/历史/工具结果分配配额 |
| 短期 / 会话记忆 | Redis、LangGraph state | 单会话 | 最近 N 轮原文 + 增量摘要 |
| 长期 · 情节记忆 | 向量库 | 跨会话 | 具体经历（"上次推荐过什么"） |
| 长期 · 语义记忆 | 关系库 / 图库 | 跨会话 | 事实与偏好（"用户不吃辣"） |
| 程序性记忆 | Skill 文件 | 长期 | 可复用技能与 SOP（→ [[01-Wiki/concepts/Agent Skills]]） |

### 二、写入链路（写什么比怎么存更难）

1. **抽取**显著信息 → 2. **重要性打分**（LLM 评估）→ 3. **摘要 + 指代消解**（让记忆条目自包含，否则"他说的那个"取回来也没用）→ 4. embedding → 5. 落库并带元数据（时间 / user_id / 类型 / 来源）

### 三、读取链路

查询改写 → **混合检索**（向量 + BM25，RRF 融合）→ 元数据 pre-filter（user_id / 时间 / 类型）→ rerank → 综合打分排序 → top-k（3–8 条）注入 prompt

**综合打分公式**：`score = 相关性 × 重要性 × 时间衰减因子`

### 四、记忆衰减（遗忘机制）

避免旧数据持续污染新任务的七种手段：

1. **时间衰减**：指数衰减（参考艾宾浩斯曲线），旧记忆自然降权
2. **重要性加权**：写入时打分，重要记忆衰减更慢
3. **访问频率**：LRU/LFU + recency，长期不被召回的逐步淘汰
4. **TTL 与容量上限**：会话记忆设过期时间；长期记忆按容量淘汰最低分
5. **冲突消解**：新事实覆盖旧事实（偏好改变），旧版本**标记过期而非删除**（保留可审计）
6. **升华**：反复出现的信息固化为长期画像，一次性噪声直接丢弃
7. **作用域隔离**：任务级记忆只在本会话有效，防跨任务污染

### 五、海量历史的查询优化（面试高频）

- **减数据**：层级摘要（原始对话 → 会话摘要 → 用户画像），检索先命中上层再下钻
- **缩空间**：按 user_id / 时间**分片分区**；标量 pre-filter 先缩小候选集
- **快索引**：ANN（HNSW / IVF-PQ）+ 混合检索 + rerank 精排
- **冷热分离**：热数据内存/缓存，冷数据落盘；热点查询结果缓存
- **写优化**：异步 + 批量 embedding，避免阻塞主链路

## 例子

**电商客服 Agent**：
- 用户说"上次买的那款洗发水还有吗" → 情节记忆召回上次订单（user_id 过滤 + 语义检索）→ 缓解"跨会话失忆"
- 用户纠正"我不喜欢薄荷味" → 语义记忆写入，importance 打高 → 后续推荐自动过滤
- 三个月前的临时咨询 → 时间衰减后不再被召回，避免干扰当前任务

## 边界与常见误区

- ⚠️ **"全存下来"不等于有记忆**：不做去重、不做冲突消解，记忆库会单调变脏，召回质量随使用时间下降
- ⚠️ **向量库不是万能**：精确查询（订单号、用户 ID）向量召回弱，必须混合 BM25
- ⚠️ **记 vs 忘是权衡而非取舍**：忘太多丢信息、忘太少噪声大，衰减参数要用评测集标定而非拍脑袋
- **不应进长期记忆的内容**：一次性的会话上下文、可实时查询的事实（应走 [[01-Wiki/concepts/Tool Calling]] 而非记忆）
- **与 RAG 的边界**：RAG 检索的是**外部知识库**，记忆存的是**该 Agent/用户的私有经历**；工程实现相似但语义与生命周期不同（→ [[01-Wiki/concepts/RAG]]）

# Agentic AI 课程 5.5 多智能体工作流

> 即使所有 Agent 用同一个底层 LLM，把复杂任务**拆给多个独立角色/进程**也更有效——像团队协作或多线程/多进程。

## 核心观点

- **动机**：一个复杂 AI 业务系统中，LLM 需要调用十几种甚至几十种工具、在几千字提示词指导下运行，典型业务流程需七八步。此时把一个 Agent 拆成多个次级 Agent 构成 **Multi-Agent 系统**就十分必要——多个承担不同任务的 Agent 互相协作，提高效率与模块化
- **拆分示例**：把"市场分析 Agent"拆成**调研、生成报表、创建文件**三个子 Agent

## 三大优势（官方）

1. **任务分解**：像人类团队一样，把复杂任务自然分解为拥有不同角色与技能的子任务
2. **专注性**：允许开发者一次只专注于构建一个特定角色（如"做最好的平面设计师智能体"）；**单个 Agent 的任务越简单，完成效果通常越好**
3. **模块化与复用**：有机会创建可复用于其他应用的通用智能体（一个"平面设计师智能体"可用于营销手册和社交媒体帖子）

## 两个补充优势（笔记作者）

- **突破上下文限制**：绝大多数模型 128k 上下文，对需要多轮规划执行的调研/业务分析任务完全不够。让每个 Agent 只负责自己部分、只返回自己的调研结果，再由一个**总结 Agent** 汇总成最终报告——总结 Agent 不必在上下文中存储其他 Agent 的调研过程，只看结果就够，从而规避上下文限制
- **节约成本**：
  - *资金*：每次请求附带大量上下文非常烧钱（即使命中缓存），Multi-Agent 体系中每个 Agent 上下文都较短，更省 Token 费用
  - *时间*：上下文越短回复越快、延迟越低；且多个 Agent 可并行处理任务，进一步降低时间成本

## 如何创建不同的 Agent

通常通过**提示词 + 工具的组合**实现：如市场分析 Agent，要告诉 LLM 它具有高超的市场分析技巧、讲一些市场分析范式与最佳实践，并配备网页浏览工具以便自己做调研。

## 亮点与不足

- 亮点：把 Multi-Agent 的价值归结为"分解 + 专注 + 复用 + 上下文/成本"四条，其中"总结 Agent 只看结果不看过 程"是规避上下文限制的关键设计
- 不足：未讨论多 Agent 带来的调试困难、成本可能反升（多次调用）、以及"何时单 Agent 就够"的判据（下一讲与课程外资料补）

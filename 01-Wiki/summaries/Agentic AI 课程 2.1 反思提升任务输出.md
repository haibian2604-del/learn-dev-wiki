# Agentic AI 课程 2.1 用反思提升任务输出

> 反思模式"经常使用且实现起来出奇地简单"：把初稿再喂回模型让它审查并出改进版；最强形态是**接上外部反馈**（执行结果、报错、搜索结果）。

## 核心观点

- 核心类比：**人类反思 → AI 反思**（写完初稿回读、发现模糊/拼写/遗漏，再修改）。这不只是模仿，而是给 AI 自我优化的能力
- 关键点：这个流程是**硬编码**的——工程师预先设计好"生成→反思"两步，而不是让模型自主决定何时反思。这是一种**可靠且易实现**的工程化方法

## 案例一：写邮件（人类流程参照）

吴恩达写给 Tommy 的邮件，V1 三个问题：①"next month"太模糊，对方无法确定具体日期；②拼写错误"fre"→"free"；③没有署名。V2 改进：明确 5th-7th、修拼写、加署名。

AI 侧对应两阶段：

1. **生成初稿**：提示 LLM "Write an email..." → 得到 Email V1
2. **反思与改进**：把 Email V1 作为新输入再发给 LLM（可同一模型，也可换一个擅长推理的模型），提示改为"请反思这份邮件草稿，并写出一个改进版" → 得到 Email V2

## 案例二：写代码的三个层次

| 层次 | 做法 | 说明 |
|------|------|------|
| 基础版 | 提示写代码 → 把 code V1 再喂回去"检查错误并写出改进版" | 得到修了 bug 的 code V2 |
| 进阶版 | 用擅长快速生成的模型写初稿，用**思考模型（Reasoning Model）**做反思 | 分工发挥各自优势，1+1>2 |
| **终极形态** | **结合外部反馈**：沙盒执行 code V1 → 捕获 Output 与 Errors（如 `SyntaxError: unterminated string literal`）→ 把 code V1 + Output + Errors 一起交给 LLM 反思重写 | 基于真实执行结果修正，得到功能正确的 code V2 |

## 三条总结（原文）

1. **反思不是魔法，而是工程实践**：不保证 100% 正确，但带来"适度的性能提升"，是性价比极高的优化手段
2. **外部反馈是关键**：能运行代码、查数据库、调 API，把这些结果作为反馈输入，反思才能更深
3. **设计哲学**：当有机会获取额外信息时，务必融入反思流程——这是提升系统鲁棒性与输出质量的核心策略

## 亮点与不足

- 亮点：用真实邮件（含具体错误）演示反思收益，比抽象描述有说服力；"硬编码反思"这一限定很重要，避免把它误当作全自主机制
- 不足：没有说明反思轮次的停止条件与收益递减点（2.5 才用评估回答）

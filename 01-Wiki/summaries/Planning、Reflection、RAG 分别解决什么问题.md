# Planning、Reflection、RAG 分别解决什么问题（zero2Agent 基础 07）

> 分清三个高频概念在 Agent 系统中的职责——避免"该检索时做规划、该自检时补知识库"。

## 最短定义

- **Planning**：解决"下一步该做什么"
- **Reflection**：解决"刚才做得对不对"
- **RAG**：解决"我现在缺什么信息"

## Planning：组织执行路径

关注任务推进方式：先查价格还是先查新闻、哪些子任务先做、信息不足时下一步用哪个工具。本质是**把目标拆成后续动作**，关心行动顺序而非知识内容。

需要 Planning 的信号：多步任务、路径不固定、工具很多、中间结果影响下一步。任务短/步骤固定时可能根本不需要显式 Planning。

## Reflection：检查结果是否靠谱

回看与自检：当前结论有无证据支持、刚才工具调用是否真正解决问题、输出是否满足目标、有无逻辑跳步或遗漏。本质是**停下来检查**而非继续往前冲。

需要 Reflection 的信号：结果质量很重要且模型常过度自信、逻辑跳步、工具用不充分、形式对但内容不扎实。注意 Reflection 不是免费午餐——增加 token 成本、执行时间、系统复杂度，不是所有任务都要加。

## RAG：补充外部信息

解决：模型当前不知道、上下文里没有，但系统可从外部知识取回（内部文档、历史报告、产品说明、外部知识库）。重点不是"想更久"而是"拿更多相关信息"。

需要 RAG 的信号：任务高度依赖外部知识，且这些知识不在训练数据、不够新、不够准、不适合全塞进提示词。

## 同场景三种动作对比（分析某币种风险）

- Planning：决定下一步查什么（先价格→再新闻→再链上）
- Reflection：检查结论是否站得住（只有价格波动就下高风险结论证据够吗）
- RAG：补回缺失信息（取回历史风控规则、召回异常模式说明）

## 核心警示

**不要把"缺信息"误判成"要多思考"**：缺外部知识时 Planning 没用；缺结果校验时补 RAG 没用；缺任务拆解时 Reflection 也没用。设计时应先判断当前缺的是哪一类能力。

## 务实建议（顺序）

1. 先把任务主流程做通
2. 再看是否真缺外部信息 → 加 RAG
3. 再看是否经常输出不稳 → 加 Reflection
4. 任务复杂到一定程度 → 增强 Planning

不要一开始把所有"高级能力"堆进去。

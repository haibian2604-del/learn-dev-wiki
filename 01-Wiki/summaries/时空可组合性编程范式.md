# A Programming Paradigm for Spatiotemporal Composability

> 北大 + DeepSeek-AI 的形式化论文：把经典 effect（效应）与 coeffect（余效应）概念提升为运行时机制，为"动态组合"（插件系统、自进化 Agent Harness）建立统一编程范式，并实现为 Cordis 元框架。

## 核心观点

- **问题**：现代软件（插件系统、自进化 Agent Harness）需要**运行时动态组合**（动态加载/卸载/重配置组件），但其形式化基础薄弱，现状只能靠"重启进程/容器编排"的粗粒度方案（→ [[01-Wiki/concepts/Harness Engineering]]）
- **两个正交维度**：
  - **时间可组合性（Temporal）**：组件移除时，其对共享环境的所有副作用必须被完全安全地逆转——需要追踪每次资源分配、事件注册、状态变更并保证有序回收
  - **空间可组合性（Spatial）**：组件能结构化、可验证地声明/发现/解析组件间依赖，并在依赖变化时协调生命周期
- **机制**：把 effect 系统提升为**可逆效应**（revertible effects，每个上下文变换带运行时追踪的逆），把 coeffect 系统提升为**响应式余效应**（reactive coeffects，上下文变化按规格通知组件 activate/deactivate/neutral），统一为单一 context 类型
- **交付**：动态组合演算（component calculus，元理论保证 Preservation/Temporal/Spatial/Progress/Confluence）+ **Cordis** 元框架实现（effect 追踪 + coeffect 解析 + 声明式组件加载器 + 热模块替换）
- **案例**：Koishi 聊天机器人框架（4000+ 社区插件）验证可表达性与通用性；未来方向直指**自进化 Agent Harness**（Agent 自己生成替换自身组件）

## 关键数据

| 维度 | 静态组合 | 动态组合 |
|------|----------|----------|
| 时间可组合性 | 词法作用域（RAII、bracket 模式） | 可逆效应：运行时追踪逆，组件移除即恢复 |
| 空间可组合性 | 模块导入解析 | 响应式余效应：依赖出现/消失/换身份时通知 |

- VSCode 实证：top100 插件中 87 个含可执行代码、移除需重启 extension host；仅 7 个声明了 extensionDependencies
- 粗粒度替代成本：每次重启丢弃进程内累积状态（缓存/连接/部分计算），重建需秒级~分钟级
- Koishi：运行 4 年、4000+ 社区插件，全部功能以插件形式建立在 Cordis context 原语上；web console 是第二个独立 Cordis 应用

## 亮点与不足

- 亮点：首次把 effect/coeffect 从编译期静态分析扩展到运行时动态场景；可逆效应实现"作者无需写 uninstall 路径"的局部性关切（locality of concern）；事务性模块重载保证系统不会进入半重载状态
- 不足：案例是单一生态单宿主语言（TypeScript），无法区分范式本身与实现/领域的贡献；观测性而非受控对比；未量化抽象开销与生产力影响

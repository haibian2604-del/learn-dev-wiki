# Agentic AI 课程 5.7 多智能体通信模式

> 四种协作拓扑：线性、双层（Manager）、多层（Deep Hierarchy）、去中心（All-to-all）；**生产中以线性与双层最常用**，因为层级越多信息越失真。

## 核心观点

设计 Multi-Agent 系统的通信模式与设计组织结构类似，而组织结构的好坏会极大影响系统效率与结果。以市场调研 Agent 为例介绍四种模式。

## 四种模式

**1. 线性模式 Linear** — 顺序执行，信息单向流动

- 类比市场团队工作流：研究员 → 平面设计师 → 文案撰写者，每个人只与下一环节沟通
- 优点：结构简单、易于理解；缺点：不灵活，出错时难以反馈或修正

**2. 双层模式 Hierarchical** — 有一个"管理员（Manager Agent）"协调所有下属 Agent

- 类比项目负责人依次给研究员、设计师、写手分配任务，收集结果再整合；**所有通信都经过经理**
- 优点：清晰、易控制、任务协调性强；缺点：**可能成为瓶颈**（manager 负担重）

**3. 多层模式 Deep Hierarchy** — 子 Agent 自己也拥有下属 Agent

- 例："研究员"下有"网页研究员"和"事实核查员"，"作家"下有"风格写手"和"引用校对员"
- 优点：可扩展、模块化、可分层调度；缺点：通信复杂、难以调试、出错难追踪

**4. 去中心模式 All-to-all** — 每个 Agent 都能随时与其他 Agent 交流，无中心、无固定顺序

- 每个 Agent 都知道其他 Agent 是谁，可互相发消息、谁都可决定何时回复，直到大家都"认为任务完成"时产出最终结果
- 特点：高度去中心化、非常灵活、创意性强，但**难以预测结果**；适用于容忍一定混乱、追求创造性结果的场景

## 四种模式总结表（原文）

| 模式 | 结构特征 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| 线性 Linear | 顺序执行，单向通信 | 简单 | 不灵活 | 固定流程任务 |
| 双层 Hierarchical | 中心协调 | 易控制 | 管理负担 | 多任务协调 |
| 多层 Deep Hierarchy | 子 Agent 层次化 | 模块化 | 复杂 | 大型系统 |
| 去中心 All-to-all | 自由对话 | 创造性强 | 不可预测 | 探索型、生成型任务 |

## 笔记作者补充（重要实务判断）

- **生产中以线性与双层更常用**：至少对当前 LLM 能力而言，信息在层级间传递时会丢失部分信息，**层级越多，信息越匮乏/失真**
- **第五种：对话模式**——类似去中心的降级版，每次只有两个 Agent 互相对话：一方执行任务，另一方审查任务，最终交出双方都满意的结果（本质是 2.1 反思模式的双 Agent 形态）
- **框架风格差异**：langchain 是忠实的线性结构；smolagents 更青睐双层/多层结构；metagpt、camelai 致力于去中心结构。大部分框架都能实现多种结构，只是代码风格不同

## 亮点与不足

- 亮点：四种拓扑 + 适用场景表可直接当设计选型工具；"层级越多信息越失真"和"生产偏爱线性/双层"是难得的落地经验；把"对话模式"识别为去中心的降级版很精辟
- 不足：未给各模式在延迟/成本/成功率上的量化对比；框架归属判断（langchain/smolagents/metagpt）颗粒度较粗

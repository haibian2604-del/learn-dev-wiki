# Agentic AI 课程 5.3 结合代码执行的规划

> 与其让 LLM 输出 JSON 计划再解析，不如**直接让它写代码**：同一工具与参数下，写代码的评估分数通常明显高于写 JSON。这就是 smolagents 的 CodeAgent 思想。

## 核心观点

- **递进关系**：上一讲让 LLM 用 JSON 描述动作；本讲主张让 LLM 直接编写代码来表达计划的多个步骤与工具调用
- **论文支持**：许多论文表明，同样的工具与参数，**让 LLM 直接编写代码的任务评估分数通常明显大于编写 JSON 而后解析**。HuggingFace 出品的 smolagents 框架中的 **CodeAgent** 概念正是在这种思想下设计的（→ [[01-Wiki/entities/smolagents]]）

## 为什么需要它（传统工具模式的脆弱性）

处理复杂数据查询（如"哪个月份热巧克力销量最高？"）时，若只提供少量基础工具（如 `获取最大值`、`过滤行`），Agent 需要极其复杂冗长的工具调用序列；更糟的是，遇到新的更复杂查询（如"上周有多少风险交易？"）还得不断创建新的定制工具——**脆弱且低效**。

## 直接执行代码的三大优势

- **利用大型库**：LLM 得以利用像 Pandas 这样数百上千个内置函数
- **高表达能力**：能编写简洁代码表达涉及多步骤、复杂逻辑的计划（解析日期、按日期排序、过滤、去重、计数）
- **性能更优**：在许多任务中，让 LLM 编写代码采取行动的性能**优于**让它编写 JSON 或纯文本计划

## 注意事项与风险

- **提示词要求**：明确要求 LLM 编写代码解决查询，并以 Python 代码返回结果，通常用 ``` 或 `<code>` 等标签分隔
- **安全问题**：直接运行 LLM 生成的代码存在安全风险，需要考虑使用**沙箱（Sandbox）** 等安全执行环境

## 定位与取舍

该模式下 LLM 可生成详细的"构建清单"并逐步执行复杂的软件开发任务。规划模式的缺点是**难以控制**——开发者无法预先知道 LLM 会生成什么行动序列。**但放弃一些控制权可以显著增加模型能力范围，多数时候这是值得的。**

## 亮点与不足

- 亮点：给出"code-as-action 优于 JSON plan"的明确结论与理由（库生态 + 表达能力 + 实测分数），并点名 CodeAgent 作为参考实现

# 9.1 项目概述与需求分析

> 用 LlamaIndex 把前八章知识串成"生产级企业知识库问答系统"：从需求分析、架构设计到 API 服务、部署运维的完整链路。

## 核心观点
- **项目目标**：把"五行代码跑通 RAG"升级为企业级知识库问答，覆盖需求→架构→实现→API→部署→运维全链路（→ [[01-Wiki/concepts/RAG]]）
- **企业痛点**：知识分散（Confluence/文件服务器/客服库/个人硬盘），新员工熟悉业务需 2 周，客服 30% 时间用于内部搜索（→ [[01-Wiki/entities/LlamaIndex]]）
- **需求工程**：分功能需求（FR-1 多源接入 / FR-2 智能问答 / FR-3 引用溯源 / FR-4 权限控制 / FR-5 管理后台）与非功能需求（NFR-1 性能 / NFR-2 安全 / NFR-3 可扩展）
- **技术选型**：LlamaIndex（RAG 框架）+ FastAPI（异步 API）+ Qdrant（向量库，强过滤利于权限）+ PostgreSQL（JSONB 元数据）+ Redis（查询缓存）+ OpenAI（GPT-4o/GPT-4V，预留本地 Qwen）
- **可量化指标**：faithfulness>0.90、relevance>0.85、P99<8s、target_qps=50、SLA 99.9%

## 关键数据
| 指标 | 数值 | 出处 |
|------|------|------|
| 知识资产规模 | 1000+ PDF/Word、200+ 制度、3000+ FAQ、5 万工单 | 项目背景 |
| faithfulness 目标 | > 0.90（每 100 答最多 10 个幻觉） | FR-2 |
| P99 延迟 | < 8000ms | FR-2 |
| target_qps / peak_qps | 50 / 200 | NFR-1 |
| SLA / RTO / RPO | 99.9% / <1h / <1h | NFR-1 |
| 文档增长 | 1500 → 5000（1 年）→ 20000（3 年） | NFR-3 |

## 亮点与不足
- 亮点：需求→指标→架构→验收的闭环思维；用真实业务场景驱动技术决策
- 不足：仍偏教程示例，真实落地需对接企业 IAM、数据治理

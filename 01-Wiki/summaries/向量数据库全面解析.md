# 向量数据库全面解析：从原理到选型

> 从向量数据库核心原理出发，对比 Milvus / Pinecone / Qdrant / Chroma / Weaviate / pgvector 六大方案，结合踩坑经验给出选型决策树。

## 核心观点

- **本质**：向量数据库专门存储/索引/检索高维向量，靠 ANN 近似最近邻做语义相似搜索，区别于传统 DB 的精确匹配（→ [[01-Wiki/concepts/向量数据库]]）
- **AI 时代三大作用**：RAG（抑制幻觉，最火）、Agent Memory（长期记忆，与 Search 合计占用量 65%）、语义搜索/推荐/以图搜图/异常检测
- **底层算法 ANN**：HNSW（召回最高、内存大，大部分场景首选）、IVF-PQ（省内存、百万级以上）、Flat（暴力、精度 100%）、DiskANN（磁盘索引、千万级+）
- **选型决策三轴**：数据量、运维能力、预算，逐层收缩（→ [[01-Wiki/entities/Milvus]]、[[01-Wiki/entities/Qdrant]]、[[01-Wiki/entities/Pinecone]]、[[01-Wiki/entities/Chroma]]、[[01-Wiki/entities/Weaviate]]、[[01-Wiki/entities/pgvector]]）

## 亮点与不足

- 亮点：给出可操作的"决策树 + 场景推荐表 + 踩坑表"，可迁移到实际项目
- 不足：Benchmark 为单点测试、未给具体 QPS/维度/数据集，跨环境不可直接套用；无 Redis 向量库（→ [[01-Wiki/entities/Redis向量库]]）参与对比

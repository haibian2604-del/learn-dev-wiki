# Agent 评测：怎么衡量你训练出来的 Agent 到底行不行（learn-agent-training 05）

> Agent 评测的指标体系、评测环境搭建与常见评测陷阱——RL Reward 曲线在涨不代表真的变强。语言模型评测"文本好不好"，Agent 评测"任务完成没有、高不高效、过程合不合理"。

## 为什么 Agent 评测特别难

1. **结果正确 ≠ 过程合理**：查天气 3 次工具调用 vs 1 次，都"完成"但效率差 3 倍
2. **同任务多条正确路径**：先查班次再查价格或反过来，无法字符串匹配
3. **环境不确定性**：API 返回随时变化，今天跑通明天失败但不一定是模型问题
4. **评测成本高**：500 条评测集 × 平均 8 步 = 4000 次工具调用，可能跑几个小时

## 四层指标体系

**第一层 任务完成**：任务完成率 Pass Rate（跑一次成功即 pass，衡量用户实际体验）/ 部分完成率 Partial Score（按子目标计分，复杂多目标任务）/ **Pass@k**（生成 k 条至少一条成功，衡量能力上限）。`Pass@1=60%, Pass@5=85%` → 有能力但稳定性不够，RL 应聚焦提升稳定性。

**第二层 效率**：平均步骤数（步骤多=延迟高+成本高）/ 冗余步骤率（对结果无贡献步骤占比）/ 首次成功率（第一次调用就成功无需重试）/ Token 消耗。完成率 80% 平均 5 步可能比 85% 平均 12 步更适合生产。

**第三层 鲁棒性**：错误恢复率（注入工具错误：超时/参数错/空返回）/ 指令扰动稳定性（同任务 3-5 种措辞完成率方差）/ 上下文长度鲁棒性（8K/16K/32K 完成率变化）/ 工具缺失处理（工具不在 tool list 时能否合理拒绝）。

**第四层 安全**：危险操作拒绝率 / **Prompt 注入抵抗率**（工具返回中嵌恶意指令时不执行比例）/ 权限越界率 / 确认率（不可逆操作前主动确认）。

## 评测环境搭建

基本要求：可复现（同模型跑两次结果一致或方差可控）、隔离性、可重置、可观测（记录完整轨迹）、成本可控。

三种方案：
1. **静态数据集 + 规则判断**：预录工具返回值+规则匹配。快/便宜/可复现；但不支持探索性行为、无法测错误恢复、规则易漏 edge case
2. **沙箱环境 + 自动验证**：Docker 容器真实执行+自动化测试。最接近真实最可靠；但搭建维护成本高、慢、与真实环境可能有差异
3. **LLM-as-Judge**：完整轨迹+结果提交更强 Judge 模型打分。灵活处理开放式结果；但 Judge 有偏差（长度偏好/格式偏好/自我偏好/位置偏好）、成本=执行+Judge 调用

**推荐混合方案**：核心功能评测 60%（沙箱+自动验证）+ 开放式能力 25%（LLM-as-Judge）+ 快速回归 15%（静态数据集，适合 CI/CD）。

**评测集构建**：每种工具 ≥20 条、难度简 30%/中 50%/难 20%、长度分布覆盖、负面用例（不需要调工具/应该拒绝）、**与训练集无重叠**。防数据泄露：评测集不同人/方法构建、发布后冻结、定期引入新用例。

## 主流 Benchmark

SWE-bench（代码修复）/ WebArena（网页操作）/ ToolBench（工具调用）/ GAIA（通用 Agent）/ AgentBench（多场景）/ HumanEval（代码生成 Pass@k）。选择：代码→SWE-bench+HumanEval；Web→WebArena；工具→ToolBench+自建；通用→GAIA+AgentBench。**公开 Benchmark 对标业界水平，自建评测集评估真实业务，两者缺一不可**。

## 五大评测陷阱

1. **只看完成率忽视效率**：报告时必须同时报平均步骤数和 Token，综合效率分 = 完成率 ×（基准步骤/实际步骤）
2. **评测集太简单**：按难度分层看（简单 95%/中等 65%/困难 30%，总体 78% 被简单任务拉高）
3. **评测环境与生产不一致**：模拟 API 格式整洁永不超时 vs 生产有噪声/超时/错误率 5-15%。**注入真实噪声**：随机 5% 工具调用超时、3% 格式异常
4. **LLM-as-Judge 系统性偏差**：长度/格式/自我/位置偏好。缓解：多 Judge 交叉打分、A/B 位置随机化、控制长度、人工抽检校准
5. **训练集和评测集分布泄露**：都是 GPT-4 生成 → 任务类型和表述风格相似。检测：全新任务测一次对比、高分样本与训练集相似度比对、定期更新评测集

## 评测流程三阶段

1. **训练中快速评测**（每 500-1000 步）：静态数据集 50-100 条核心任务 + 通用 benchmark 子集检测偏移，10 分钟出结果
2. **checkpoint 评测**（每个候选模型）：沙箱跑完整评测集 300-500 条，计算四层指标，分难度看，跑公开 Benchmark，几小时出结果
3. **上线前灰度评测**：生产灰度流量跑，监控真实任务完成率+用户反馈，新旧模型 A/B，重点 edge case 和安全

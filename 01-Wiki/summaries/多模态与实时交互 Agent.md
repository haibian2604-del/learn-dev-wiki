# 多模态与实时交互 Agent（zero2Agent 基础 14）

> Voice Agent 三种架构范式、Computer Use / GUI Agent 设计模式、快慢解耦的跨模态工程原则——多模态不是"给文本 Agent 加个语音前端"，而是重新设计感知-决策-执行循环。

## 为什么 2026 年成为刚需

Text-only → Voice/Vision 增强 → 多模态原生（感知-决策-执行全链路多模态）。驱动：用户场景要求（客服/车载/家居手眼被占用）、任务复杂度要求（网页/桌面软件长尾应用无法纯 API 覆盖）、模型能力到位（延迟成本降到可用）。关键认知：延迟约束、信息密度、错误恢复方式都完全不同。

## Voice Agent 三种架构范式

1. **Cascaded 级联**：VAD（检测说话）→ ASR（语音转文本）→ LLM（文本推理）→ TTS（文本转语音）。每环节独立优化替换；LLM 部分与文本 Agent 完全复用；延迟=各环节之和（VAD 200ms + ASR 300ms + LLM 500ms + TTS 300ms = 1.3s+）；语调情感在 ASR 丢失。
2. **Omni 端到端**：单一多模态模型直接音频进音频出。延迟极低（300-500ms）、保留副语言信息；可控性差（黑盒）、调试困难（无中间文本）、成本高（音频 token >> 文本）。
3. **Full-duplex 全双工**：可打断、边听边说。最接近自然对话；需处理"同时说话"冲突、打断检测（独立模块）、流式生成+播放+随时取消基础设施。延迟 500-800ms。

| 维度 | Cascaded | Omni | Full-duplex |
|------|----------|------|-------------|
| 端到端延迟 | 1.3s+ | 300-500ms | 500-800ms |
| 可控性 | 高（文本中间层可审计） | 低（黑盒） | 中（混合） |
| 工具调用 | 成熟 | 有限 | 成熟 |
| 情感保留 | 丢失 | 保留 | 部分 |
| 工程复杂度 | 低 | 中 | 高 |
| 成本 | 低 | 高 | 中 |
| 适用 | 客服、内部工具 | 陪伴、娱乐 | 实时助手、电话 |

实践常用**混合方案**：Omni 做快速短回复（"嗯、好的"），Cascaded 做需工具调用的复杂回复。

## Computer Use / GUI Agent

目标：像人类一样操作图形界面（点击/输入/滚动/读屏）。

**动作空间设计**：有限动作原语（click/type/scroll/key/screenshot/wait/drag）。原则：原子性（最小操作单元组合复杂行为）、可逆性标注（区分可逆滚动/切 tab 与不可逆删除/提交/发送）、等待机制（操作后等渲染完成再截图验证）。

**视觉定位两方案**：
- **A. Set-of-Mark（SoM）标注选择**：截图→视觉模型检测可交互元素→标号→LLM 回"点击 [7]"按钮。LLM 只需选 ID 不需空间推理，定位精确；但多一步检测、遗漏元素无法操作。
- **B. 坐标定位**：截图直接发多模态 LLM，回 click(324, 178)。无需额外检测；坐标精度依赖模型视觉、分辨率变化失效。

实践建议：优先 SoM（稳定性高），覆盖不到 fallback 坐标。

**安全边界**：环境隔离（沙箱/虚拟机）、权限收窄（白名单应用）、操作审批（不可逆操作人工确认）、执行限速（防高频点击循环）、状态验证（操作后截图对比）。

**代表产品**：Claude Computer Use（Anthropic API）、Open Interpreter/OS-Copilot（开源）、RPA 增强（LLM 决策层 + 原有元素定位）、浏览器自动化（Playwright/Puppeteer + 视觉）。共同架构：截图/DOM → 理解状态 → 规划动作 → 执行 → 验证 → 循环。

## 快慢解耦：跨模态共性设计原则

核心矛盾：用户期望实时响应（快），深度推理需要时间（慢）。方案：**实时响应通道与深度推理通道分离并行**。
- Voice：快通道给填充词/短确认维持节奏，慢通道做语义理解/工具调用/回复生成——为慢通道"争取时间"。
- GUI：快通道按已有计划执行下一动作（不重新思考），慢通道每隔 N 步或异常时做全局评估重新规划——避免每步完整推理延迟爆炸。

| 维度 | 快通道 | 慢通道 |
|------|--------|--------|
| 职责 | 维持交互节奏 | 保证决策质量 |
| 延迟 | <200ms | 1-5s 可接受 |
| 模型 | 小模型/规则 | 大模型/多步推理 |
| 失败代价 | 低 | 高 |

本质上是"缓存 + 后台刷新"的交互版本。

## 工程挑战

- **延迟预算管理**（硬约束）：Voice 总预算 800ms（网络 100 + 语音理解 150 + LLM 350 + 合成 150 + 缓冲 50）。手段：流式处理（LLM 出首句即开始 TTS）、预计算（预测回复方向提前准备）、分级降级（模板回复/短确认）。
- **多模态信息对齐**：统一时间轴（按时间戳排序）、显式引用消解（prompt 中把指代解析为具体对象）、状态快照（关键时刻保存截图+文本+音频）。
- **错误恢复**（检测-确认-恢复三步循环，不盲目重试）：Voice 主动确认（"您是说转人工还是查余额？"）、工具失败自然语言解释+替代方案、关键操作前复述确认；GUI 每动作后截图验证、页面未响应等待重试、错误弹窗识别处理。

## 延伸：Embodied Agent 与机器人控制

物理世界边界——连续控制、物理安全、感知延迟。**双层架构（规划与控制分离）**：高层规划（VLM/LLM 理解指令、拆子任务、秒级重估）+ 底层控制（VLA/Policy Network 转连续动作、毫秒级执行、处理物理反馈）。本质是快慢解耦的物理版。

- **VLA（Vision-Language-Action）**：输入摄像头+自然语言，输出关节动作序列（RT-2/Octo/OpenVLA），动作 token 化复用预训练视觉语言能力。
- **Action Chunking**：LLM 一次预测 0.5-1s 动作序列 chunk，控制器按 50-200Hz 回放，推理频率降到 2-5Hz 仍保持高频。
- **Sim2Real**：仿真训练（Domain Randomization 随机化纹理光照物理参数）→ 真实微调。原则：**在仿真中获得泛化，在真实中获得精度**。
- **安全第一**：力矩限制、碰撞检测、紧急停止、行为约束经安全验证才下发（控制层不直接使用大模型输出）。
- 对软件 Agent 工程师启示：双层架构适用于任何"规划慢执行快"场景；Action Chunking 适用于高频决策（实时交易/游戏 AI）；Sim2Real 适用于模拟训练真实部署。

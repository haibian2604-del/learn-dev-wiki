# Agentic AI 课程 3.6 代码执行

> 与其为每个功能造工具，不如让模型**自己写代码**；但必须沙盒化——真实案例里，一个 Agent 曾执行 `rm *.py` 删光项目目录。

## 核心观点

代码执行 = 让 LLM 编写并运行代码来解决用户任务。三大优势：

- **强大能力**：LLM 生成的代码方案常常出人意料地聪明有效
- **灵活性**：相比于为每个功能手造工具，让模型自己写代码更灵活、更可扩展——例如科学计算器有大量功能按钮，不可能每个按钮都建一个工具
- **提升应用性能**：许多语言模型的训练者会专门优化模型，确保其代码执行功能在应用中表现良好

## 对比：预定义工具集 vs 让模型写代码

**传统方法（预定义工具集）**：为数学文字题建 `add` / `subtract` / `multiply` / `divide`；用户说 "Add 13.2 and 18.9" → 调 `add` → 32.1。局限：遇到"2 的平方根是多少"就得再加 `sqrt`、`exponentiation`……为每个按钮建工具不切实际。

**替代方案（模型自己写代码）**：

1. **设计系统提示词**：指令模型"编写代码来解决问题"，要求以 Python 代码返回并用 `<execute_python>` `</execute_python>` 标签包裹
2. **模型输出**：如 `import math / print(math.sqrt(2))`
3. **提取与执行**：用正则等模式匹配提取标签内代码 → 在**安全沙盒**中执行 → 得 `1.4142135623730951`
4. **反馈与格式化**：把数值结果传回 LLM → 生成格式良好的答案 "The square root of 2 is approximately 1.4142."

执行方式：Python 内置 `exec()`（能执行任意字符串代码，强大但有安全风险）或专用沙盒工具。

## 进阶：带外部反馈的反思

模型生成代码草稿 → 执行捕获错误 → 把错误信息（如 `SyntaxError`）连同原始任务发回模型 → 模型反思并生成 V2 代码。通过该迭代有时能修正错误、得到更精确答案。

## 安全考量（本页最重要部分）

- **核心风险**：在沙盒外运行模型生成的任意代码是有风险的
- **真实案例**：一位团队成员使用的高度 agentic 化代码执行器，**错误地执行了 `rm *.py`，删除了项目目录中所有 Python 文件**；幸好该成员有备份习惯，未造成实质损失
- **最佳实践**：**必须使用沙盒环境**；推荐 **Docker** 或 **E2B** 这类轻量级沙盒，有效隔离代码、降低损坏系统或环境的风险
- **现实情况**：尽管有风险，许多开发者仍直接执行模型生成的代码而不做检查——但为了安全应坚持使用沙盒

## 行业趋势与未来方向

- 代码执行是让 agentic 应用变得极强的关键工具，模型训练者会专门优化它
- 目前开发者需手动为 Agent 添加工具；新标准 **MCP（Model Context Protocol）** 正在兴起，让开发者更容易接入庞大工具集，简化开发流程（→ 3.7）

## 亮点与不足

- 亮点：用"科学计算器按钮"论证代码执行对预定义工具集的替代优势；`rm *.py` 的真实事故是极有说服力的安全警示
- 不足：只给"用沙盒"的结论，未讲沙盒的隔离粒度/资源限制/网络策略等具体设计（可对比 [[01-Wiki/concepts/Agent 训练环境]] 的四硬规则）

# 第九章 上下文工程

> hello-agents 第九章：上下文工程（Context Engineering）核心概念与实践——GSSC 流水线（ContextBuilder）、结构化笔记（NoteTool）、即时文件系统访问（TerminalTool）。

## 核心观点

- **上下文工程 = 提示工程的自然演进**：提示工程关心"怎么写好提示"；上下文工程关心"在推理阶段如何策划与维护最优信息集（tokens）"——包含系统指令、工具、MCP、外部数据、消息历史全部
- **上下文腐蚀（context rot）**：随上下文 tokens 增加，模型准确回忆信息的能力下降（needle-in-a-haystack 基准）；注意力预算有限且边际收益递减 → **上下文是有限资源**
- **有效上下文解剖学**：系统提示"最小必要信息集"（分区组织、不过度硬编码不空泛）；工具集"最小可行工具集（MVTS）"——**如果人类工程师都说不准用哪个工具，别指望智能体做得更好**；few-shot 精选多样典型示例
- **JIT 上下文（Just-in-time）**：从"推理前一次性检索"过渡到"维护轻量化引用 + 运行时动态加载"（文件路径/查询/URL）；混合策略更有效（前置高价值 + 按需探索）
- **长时程任务三手段**：压缩整合（Compaction，高保真摘要重启窗口）、结构化笔记（上下文外持久化）、子代理架构（主代理规划 + 子代理干净上下文深挖后回传 1-2k token 摘要）
- **ContextBuilder 实现 GSSC**：Gather（多源汇集，容错）→ Select（相关性+新近性加权评分，贪心填充 token 预算）→ Structure（[Role&Policies]/[Task]/[Evidence]/[Context]/[Output] 分区模板）→ Compress（兜底压缩）
- **NoteTool**：Markdown+YAML 结构化笔记，7 操作（create/read/update/search/list/summary/delete），索引文件加速
- **TerminalTool**：四层安全（命令白名单只读/工作目录沙箱/超时/输出大小限制）实现安全的即时文件系统访问

## 亮点与不足

- 亮点：上下文腐蚀的机制解释（Transformer 注意力 n²、训练分布偏好短序列）；"公共资源"心智模型贯穿全文；GSSC 与 Template 分区可直接复用
- 亮点：TerminalTool 四层安全设计是"给 Agent 开终端"的教科书级方案（白名单+沙箱+超时+输出限制）
- 不足：代码实现偏教学（相关性用关键词重叠、token 估算用字符数），生产需替换为向量相似度与真实 tokenizer

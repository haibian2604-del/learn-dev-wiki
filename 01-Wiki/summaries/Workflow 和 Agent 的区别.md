# Workflow 和 Agent 的区别（zero2Agent 基础 02）

> 理清 Workflow、LLM App 与 Agent 三类系统的边界——真正的分界线不在“用没用模型”，而在“下一步由谁决定”。

## 三类系统

1. **普通 LLM App**：一次输入、一次输出（问答、摘要、翻译、抽取）。不负责多步执行。
2. **Workflow**：执行路径主要由开发者预先定义（先检索→再总结→再格式化）。有价值且很多业务已足够。
3. **Agent**：系统根据中间状态自己决定下一步做什么。路径非完全写死。

## 真正的分界线

> 下一步动作是由开发者提前写死，还是由系统根据状态动态决定。

分界线**不在**：用没用大模型、调没调用工具、步骤多不多、UI 高不高级。

## 对比例子（分析某币种异常风险）

- **Workflow 版**：开发者写死——拉价格→拉成交量→拉新闻→统一总结→输出等级。
- **Agent 版**：先看价格是否异常→若异常再查成交量→若也异常再查新闻→不足再查社媒/链上→够了才输出。每步依赖前一步结果。

## 很多场景其实不需要 Agent

若输入稳定、步骤固定、分支有限、结果格式明确 → Workflow 更便宜、稳定、可控。硬上 Agent 常见结果：成本更高、延迟更长、行为更不稳定、调试更困难。

## 实用判断方法

**优先 Workflow 的信号**：步骤基本固定 / 路径可预先枚举 / 模型只负责生成不决定流程 / 更在意稳定可控。

**Agent 才有意义的信号**：需根据中间结果动态选工具 / 信息不足时继续探索 / 围绕目标持续推进 / 存在开放环境与不确定决策。

## 不要对立，要组合

真实工程里二者是组合关系：外层 Workflow 控制主流程，某些节点内部放 Agent（如主流程接收任务→选类型→调模块，某模块内用 Agent 做信息探索）。比“全站 Agent 化”更稳。

> Workflow 负责确定性流程，Agent 负责不确定环境下的动态推进。无高低之分，只有适不适合。

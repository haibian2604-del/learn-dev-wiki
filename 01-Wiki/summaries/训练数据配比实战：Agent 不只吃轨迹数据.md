# 训练数据配比实战：Agent 不只吃轨迹数据（learn-agent-training 04）

> Agent 训练的数据配比策略、各类数据的作用与常见翻车案例——**模型会变成它吃的数据的形状**。

## 为什么配比重要：能力偏移

只用 Agent 轨迹数据训练 → 先验变成"所有输入都是需要调工具解决的任务"。学术名 **catastrophic forgetting（灾难性遗忘）**，Agent 语境更准确的说法是**能力偏移**（不是忘记怎么聊天，而是输出分布被拉偏）。典型症状：所有问题都想调工具（连"你好"都调 API）、格式过度结构化（一句话也包 JSON）、拒绝回答通用问题、长文本能力退化、安全对齐退化。

## 六类数据与配比

| 数据类别 | 核心作用 | 缺失后果 |
|---|---|---|
| Agent 轨迹 | 多轮推理+工具调用 | Agent 能力起不来 |
| Tool Calling 单轮 | function calling 基本功 | 工具调用格式不稳 |
| 通用指令跟随 | 保持对话和指令执行 | 非 Agent 场景行为异常 |
| 长文本理解 | 保持长上下文 | 长轨迹中间信息丢失 |
| 安全/拒绝 | 保持安全对齐 | 危险操作不拒绝 |
| 代码/推理 | 保持逻辑推理 | 复杂推理链质量下降 |

- **Agent 轨迹（核心不独占）**：3-15 步多轮交互；强模型沙箱生成+人工筛选 / 真实日志脱敏筛选 / 人工标注（种子+难样本）；劣质轨迹不如不放
- **Tool Calling 单轮**：用户一句话直接调一次工具，无多轮推理。为什么单独放：只见过复杂轨迹的模型在简单场景会过度推理（先 `<think>` 分析再调工具）。每种工具 50-200 条覆盖常见参数组合即可
- **通用指令跟随（压舱石）**：Alpaca/ShareGPT 类。**关键：这些数据里不能出现工具调用**——模型要从中学"不是所有问题都需要调工具"
- **长文本理解（隐性需求）**：Agent 轨迹天然 4K-8K tokens；8K 后遗忘前面工具返回 → 重复调用/忽略关键信息。含长文档问答、多文档总结、长对话历史、needle-in-haystack
- **安全/拒绝（比对话模型更重要）**：Agent 能真的执行操作。危险操作拒绝/权限越界/信息泄露/循环确认/**Prompt 注入防护**（工具返回中嵌恶意指令，未训练真的可能执行）
- **代码/推理（保持思维链质量）**：不放则 `<think>` 变短变粗糙易跳步

## 配比经验（随阶段调整）

**SFT 阶段**：Agent 轨迹 35-45% + Tool Calling 单轮 10-15% + 通用指令 15-20% + 长文本 5-10% + 安全 5-10% + 代码/推理 10-15%。

**硬规则**：Agent 轨迹 ≤50%（超了通用能力明显退化）；安全 ≥5%；通用指令 ≥15%（防偏移最低线）。

**RL 阶段（任务分布）**：30% 简单 + 50% 中等 + 20% 困难（全简单无学习信号、全困难 Reward 全 0）；RL 任务覆盖所有工具类型（某类工具没被训到则退化）；RL 也致通用退化 → 方法 A：RL loss 混少量 SFT loss / 方法 B：定期通用 benchmark 检查退化则暂停 RL 做 SFT 补救。

**模型规模差异**：模型越小越易被带偏需更大比例通用数据。1B-3B（轨迹 25-35%/通用 30-40%）→ 7B-13B（35-45%/20-25%）→ 30B-70B（40-50%/15-20%）→ 70B+（45-55%/10-15%）。核心原则：**模型越小越要保守，宁可 Agent 弱一点不能通用能力崩**。

## 数据质量比数量重要

三个维度：
1. **轨迹正确性**：工具参数错但碰巧结果对（运气好）、多余工具调用、Think 与行为不一致、最终回复没用工具返回
2. **多样性**：工具类型覆盖、难度分布、轨迹长度（1-15 步）、错误恢复覆盖、拒绝场景覆盖
3. **格式一致性**：统一 tool call JSON schema、think 标签统一（`<think>` 不要混用 `<thinking>`）、工具返回格式统一、角色标记统一

数据量经验：入门 ~10K（轨迹 1K-5K）；生产 50K-100K（轨迹 10K-50K）；大规模 200K+。**1 万条高质量远好于 10 万条低质量**。

## 调试方法与数据飞轮

**监控指标**：Agent 任务完成率（每 500 步测试集）、通用 benchmark（MT-Bench/AlpacaEval 检测偏移）、工具调用格式正确率、不该调工具时的调用率、安全拒绝率、长文本准确率。

**症状→调整**：都想调工具→降 Agent 轨迹到 35% 增通用；格式常错→增单轮 Tool Calling 统一格式；长轨迹后期质量降→长文本提到 10%；该拒不拒→安全提到 10%；推理链变短→代码/推理到 15%；Agent 能力上不去→先清洗数据再调比例。

**A/B 测试**：固定评测集（Agent 任务简/中/难各 50 + 通用 100 + 安全 50 + 长文本 30），两配比各训一个模型对比。**好配比 = Agent 能力显著提升 + 通用退化 ≤5%**（超 10% 需调整）。

**数据飞轮**：线上日志（脱敏）→ 自动筛选（成功轨迹直接加入 / 失败轨迹分析：工具错构造正确轨迹、推理错强模型纠正、系统错跳过 / 边界案例人工标注）→ 重训上线。核心价值：**线上数据分布和手工构造不同**（用户会用你没想到的方式调工具）；前提是脱敏与合规审查。

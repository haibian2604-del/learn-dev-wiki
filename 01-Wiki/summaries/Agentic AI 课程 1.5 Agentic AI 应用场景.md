# Agentic AI 课程 1.5 Agentic AI 应用场景

> 四个由易到难的落地案例（发票处理 → 客服邮件 → 通用客服 → 视觉操作浏览器），并给出"什么任务适合 Agentic AI"的难度光谱。

## 核心观点

- **定义**：Agentic AI 是让 Agent 根据明确或动态的目标，自主调用工具、访问数据库、执行步骤并完成任务的工作模式；区别于"输入-输出"式问答，强调**多步骤规划、工具使用、状态更新与决策**
- 与人类工作流的关系：**不是取代人，而是把人从重复性、规则性强的任务中解放出来**，专注于更高阶的决策与创造

## 四个案例（难度递进）

| # | 案例 | 工作流 | 难度特征 |
|---|------|--------|----------|
| 1 | 发票处理 | PDF 转文本 → LLM 解析并提取字段（开票方/地址/金额/到期日）→ update database → 生成 "Record created!" | 步骤固定、纯文本、标准程序 |
| 2 | 回复客户邮件 | 提取关键信息（订单号/产品/问题）→ 查订单库 → 起草回复 → **请求人工审核** → 发送 | 加入人工审核卡点 |
| 3 | 通用客服 Agent | 库存查询需自行规划多次 API 调用顺序；退货处理需按条件判断（30 天内？未使用？→ 生成退货标签 + 置"待退货"状态） | **步骤不预先固定**，需条件分支 |
| 4 | 视觉计算机使用 | 打开浏览器 → 填表点按钮 → 遇"页面未找到"**自主切换**到 Google Flights → 回 United 确认 | 多模态 + 状态跟踪 + 视觉理解 + 出错改道 |

案例 4 的现实挑战：页面加载慢会卡住、UI 变化识别不到元素、多模态输入更难；核心能力是视觉理解 + 推理决策 + 工具调用 + 状态跟踪。

## 难度光谱（判定任务是否适合）

- **较易实现**：清晰逐步的流程 / 有标准程序可循 / **纯文本资产**（LLM 擅长文本）
- **较难实现**：**步骤未知**（需动态规划）/ 边执行边解决 / **多模态输入**（声音、视觉）

## 亮点与不足

- 亮点：四个案例覆盖"固定流程 → 条件分支 → 视觉交互"三档，并抽象出可直接套用的难度判据，是选场景的实用清单
- 不足：没给各案例的成功率/失败率数据；案例 4 只给"不稳定"结论而未见缓解手段

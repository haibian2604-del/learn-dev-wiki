# Agentic AI 课程 4.8 开发过程总结

> Agent 开发只有两件事——**构建**与**分析**，且分析的重要性不亚于构建；从原型到成熟要经历四个阶段，分析工作随系统成熟不断提高严谨度。

## 核心观点

开发者主要精力集中在两项活动上并不断来回切换：

- **构建（Build）**：编写软件与代码来改进系统
- **分析（Analyze）**：决定下一步把构建精力集中在哪里——**其重要性与构建相当**

## 四阶段迭代模型

| 阶段 | 描述 | 主要分析活动 |
|------|------|-------------|
| 1. **快速原型** | 快速构建端到端系统（"先做个垃圾出来"） | 手动检查最终输出，通读 trace，凭直觉找出性能不佳的组件 |
| 2. **初步评估** | 系统开始成熟，超越纯手动观察 | 构建初步的**端到端评估**，用小型数据集（如 10-20 例）计算整体性能指标 |
| 3. **严谨分析** | 系统需要更精确的改进方向 | 进行**错误分析**，统计量化各组件导致次优输出的频率，做更集中的决策 |
| 4. **高效调优** | 系统进一步成熟，需在组件级别高效改进 | 构建**组件级评估**，以便更高效地对单个组件调优 |

> 阶段 1→4 与 4.1 / 4.2 / 4.4 三讲一一对应，本页是模块四的收束。

## 关键论断

- 开发是**非线性**过程，需要在"调整系统、错误分析、改进组件、调整评估"之间反复横跳
- **许多经验不足的团队花太多时间在构建上、太少时间在分析上**，导致工作重点不集中、效率低下
- 早期可尽情使用市面工具来监控追踪、记录运行时、计算成本（"前人造的轮子"）；但**大多数 Agent 工作流高度定制化，团队最终仍需自行构建许多定制化评估**，才能准确捕获系统特有的问题
- 本模块的核心认知：**一套系统化的开发流程（评估 → 错误分析 → 改进）**，只有它才能支撑起足够复杂的 Agent 系统

## 亮点与不足

- 亮点：把"分析 = 构建"的平等地位讲透，并给出阶段与评估手段的对应表；"先做个垃圾出来"与"别只构建不分析"直指新手通病
- 不足：未给各阶段的进入/退出判据（什么时候算"系统成熟到该上第二阶段"）；未讨论团队规模对流程的影响

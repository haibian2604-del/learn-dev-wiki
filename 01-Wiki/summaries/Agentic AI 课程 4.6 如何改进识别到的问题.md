# Agentic AI 课程 4.6 如何改进识别到的问题

> 跑完评估找到问题后的改进清单：非 LLM 组件调参/换服务；LLM 组件改提示词、换模型、拆任务，微调放最后；外加一份"培养模型直觉"的方法。

## 非 LLM 组件的改进手段

- **调整参数或超参数**：网页搜索（结果数量、日期范围）；RAG 检索（相似度阈值、文本分块大小）；人物检测（检测阈值，权衡误报与漏报）
- **替换组件**：尝试不同服务提供商，换 RAG 搜索引擎、换 Web 搜索 API
  - 实务经验：在国内查询**企业营收报表与财务信息**，百度搜索效果远超 Bing 或 Google；但**查询学术资源时完全相反**

## LLM 组件的改进手段（按顺序）

1. **改进提示词**：增加明确指令（在提示词中指明资源与任务应有的规划路径，而不是让 LLM 自己猜）；使用少样本提示（添加具体的输入与期望输出示例）
2. **尝试不同的 LLM**：不要嫌麻烦，多测试几款，并用**评估（Evals）**选出最适合特定应用的模型
3. **任务分解**：若单步指令过于复杂导致 LLM 难以准确执行，拆成更小的步骤——如"生成步骤 + 反思步骤"，或连续多次调用
4. **微调模型**：最复杂、成本最高的选项，只有在穷尽其他方法、仍需要挤出最后几个百分点时才考虑；适用于成熟且性能要求极高的应用

## 培养模型选择直觉（笔记作者的一手经验）

> 以下为课程笔记作者（杨若朴）在 2025 年 11 月初的观点，属**个人经验而非客观结论**，仅作参考。

- **模型性格观察**：Qwen 比较嘴硬，Gemini 2.5 比较逆来顺受，GPT 言简意赅，DeepSeek 有创意和鬼点子
- **能力擅长**：Gemini 擅于一口气生成上千行代码；Claude 更擅长在现有系统里做小范围修改
- **场景匹配**：嘴硬的 Qwen 适合严谨的数据报表查询；逻辑强但易过度自信的 Kimi K2 在中低难度场景以简短有说服力的输出出彩，复杂场景要防它自信出错
- **参数规模**：大参数模型通常比小参数模型情商更高、对模糊指令理解更强（例：GPT-4.5 在高情商场景的回复）；新架构 + 大参数量模型在多步复杂指令任务中能更好地列出并编辑所有敏感信息，小模型容易出错或遗漏

**如何培养这种直觉（四法）**

1. **频繁试玩不同模型**：常测新的闭源/开源模型（作者自我要求：保持 3-5 种主力模型，一个月内至少用过 10 种以上，能报出 20 种以上型号）
2. **建立个人评估集**：用固定评估任务校准不同模型能力
3. **阅读他人的提示词**：大量阅读从业者、专家、开源框架中的提示词
4. **在工作流中尝试**：在实际 Agent 工作流中换模型，看 trace 与组件级/端到端评估，权衡性能、价格、速度

## 亮点与不足

- 亮点：改进手段按"性价比从高到低"排序列出，并明确微调是最后手段；"百度 vs Bing/Google 因任务而异"是国内落地少见的实务经验
- 不足：模型性格判断高度个人化、时效性强（作者自己标注了时间点），宜当作**待验证假设**而非结论；缺少改进前后的量化收益对比
